Markdown convierte texto plano en documentos estructurados y legibles. Es el lenguaje estándar para README, wikis, issues y documentación técnica en plataformas como GitHub.

Qué es Markdown y por qué usarlo

Markdown es un lenguaje de marcado ligero creado para que el texto fuente sea legible por sí mismo y, a la vez, fácil de convertir a HTML u otros formatos. En lugar de etiquetas verbosas, usa símbolos simples (#, *, -, `) para expresar estructura: títulos, énfasis, listas, enlaces y bloques de código. La especificación de referencia más adoptada es CommonMark, que busca un comportamiento consistente entre implementaciones.

Se usa en README de repositorios, documentación, foros, gestores de tareas, generadores de sitios estáticos y notas técnicas. Su ventaja principal es la portabilidad: texto plano que vive bien en control de versiones y se diffs con claridad.

Markdown “sabores”

Además de CommonMark, plataformas como GitHub añaden extensiones (GitHub Flavored Markdown, GFM): tablas, listas de tareas, tachado y autolinks. Si tu documento debe ser portable, prioriza sintaxis compatible con CommonMark y usa extensiones cuando el destino las soporte.

Estructura: títulos, párrafos y énfasis

Los títulos se crean con # (uno por nivel). Un documento bien estructurado usa un solo # principal y jerarquiza secciones con ##, ###, etc. Separa párrafos con una línea en blanco; los saltos de línea simples suelen colapsarse según el renderizador.

# Título del documento
## Sección
### Subsección

Párrafo con **negritas**, *cursivas* y `código en línea`.

> Una cita en bloque puede resaltar notas o advertencias.

Usa énfasis con moderación: negritas para términos clave, cursivas para matices, y evita gritar en mayúsculas. La claridad tipográfica mejora la escaneabilidad de la documentación.

Escribe textos de enlace descriptivos (“ver guía de instalación”) en lugar de “clic aquí”. En imágenes, el texto alternativo (alt) es esencial para accesibilidad y cuando la imagen no carga. Para documentación técnica, enlaza a secciones, issues o archivos relativos dentro del repositorio.

Código y bloques técnicos

El código en línea se encierra en acentos graves (`). Los bloques de código usan fences de triple acento grave y pueden indicar el lenguaje para resaltado de sintaxis:

```bash
git clone https://github.com/usuario/proyecto.git
cd proyecto
npm install
```

```python
def saludar(nombre: str) -> str:
    return f"Hola, {nombre}"
```

Prefiere bloques con lenguaje especificado (json, yaml, sql, bash) para legibilidad. Muestra comandos copiables y, cuando aplique, la salida esperada por separado para no confundir al lector.

Tablas y listas de tareas (GFM)

GitHub y otros renderizadores soportan tablas y checklists:

| Servicio | Uso principal | Ejemplo |
|----------|---------------|---------|
| EC2      | Cómputo VM    | Servidor web |
| S3       | Objetos       | Backups |

- [x] Configurar entorno
- [ ] Escribir pruebas
- [ ] Desplegar

Buenas prácticas para docs técnicas

  • Empieza con propósito: qué hace el proyecto, para quién y cómo empezar rápido (Quickstart).
  • Estructura predecible: instalación, configuración, uso, ejemplos, troubleshooting, contribución y licencia.
  • Ejemplos reales: comandos y fragmentos probados; indica prerrequisitos y versiones.
  • Un tema por sección: títulos claros, párrafos cortos y listas cuando enumeres pasos u opciones.
  • Mantenibilidad: evita duplicar información; enlaza a la fuente canónica y actualiza docs junto al código.
  • Accesibilidad: texto alternativo en imágenes, contraste adecuado en diagramas exportados y jerarquía correcta de encabezados.

Un buen README responde en minutos: “¿qué es?”, “¿cómo lo ejecuto?” y “¿dónde pido ayuda?”. La documentación es parte del producto: reduce fricción para usuarios y colaboradores.

Markdown en flujos reales

En GitHub, los archivos README.md, CONTRIBUTING.md y wikis renderizan automáticamente. En issues y pull requests, Markdown permite comunicar contexto, pasos para reproducir y resultados esperados con claridad. Generadores como MkDocs, Docusaurus o Jekyll convierten colecciones de Markdown en sitios de documentación navegables.

Adopta convenciones de equipo (estilo de títulos, longitud de línea, idioma) y usa linters o previsualización para mantener consistencia. Con estas prácticas, Markdown se convierte en una herramienta simple pero poderosa para documentar sistemas y compartir conocimiento técnico.
