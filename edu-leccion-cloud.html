Cloud

Cloud básico:
AWS / Azure / GCP

La nube permite consumir infraestructura y servicios bajo demanda. Conoce los conceptos comunes entre Amazon Web Services, Microsoft Azure y Google Cloud para elegir y operar recursos con criterio.

Qué es cloud computing

La computación en la nube entrega recursos de TI (servidores, almacenamiento, bases de datos, redes, analítica, IA) a través de Internet con un modelo de pago por uso. En lugar de comprar y mantener hardware propio, provisionas capacidad cuando la necesitas y la liberas cuando no. Los proveedores operan centros de datos globales y exponen servicios mediante consola web, CLI y APIs.

Beneficios típicos: elasticidad (escalar arriba/abajo), alcance global, velocidad de aprovisionamiento y conversión de gasto de capital (CapEx) en gasto operativo (OpEx). También introduce responsabilidades nuevas: gestión de costos, seguridad de configuración y diseño para resiliencia.

Modelo de responsabilidad compartida

El proveedor asegura la seguridad de la nube (infraestructura física, hardware, red base). El cliente es responsable de la seguridad en la nube: configuración, identidades, datos, cifrado, parches del sistema operativo en IaaS y control de accesos. El alcance varía según el servicio.

Modelos de servicio: IaaS, PaaS, SaaS

  • IaaS (Infrastructure as a Service): máquinas virtuales, redes y almacenamiento administrados a bajo nivel. Tú gestionas SO, runtime y aplicaciones. Ejemplos: Amazon EC2, Azure Virtual Machines, Google Compute Engine.
  • PaaS (Platform as a Service): la plataforma gestiona infraestructura y runtime; tú te enfocas en código y datos. Ejemplos: AWS Elastic Beanstalk, Azure App Service, Google App Engine/Cloud Run (según enfoque).
  • SaaS (Software as a Service): aplicación lista para usar vía suscripción. El proveedor opera casi todo; tú administras usuarios y datos. Ejemplos: Microsoft 365, Google Workspace.

Elegir el modelo implica balancear control vs. carga operativa. Para aprender fundamentos, IaaS revela cómo funcionan redes y servidores; para entregar rápido, PaaS y servicios gestionados suelen ser más eficientes.

Regiones, zonas y diseño resiliente

Los tres grandes proveedores organizan su infraestructura en regiones geográficas (p. ej. este de EE.UU., São Paulo, Europa) compuestas por múltiples zonas de disponibilidad (datacenters aislados con alimentación y red independientes). Desplegar en varias zonas mejora tolerancia a fallos; desplegar en varias regiones mejora cercanía a usuarios y continuidad ante eventos regionales.

Conceptos transversales: latencia (elige región cercana a tus usuarios), residencia de datos (cumplimiento normativo) y servicios globales vs regionales. Antes de producción, define objetivos de disponibilidad y recuperación (RTO/RPO).

Servicios esenciales por categoría

Cómputo

AWS: EC2 (VMs), Lambda (serverless). Azure: Virtual Machines, Functions. GCP: Compute Engine, Cloud Functions/Cloud Run. Permiten ejecutar desde procesos event-driven hasta servidores de larga duración.

Almacenamiento

Objetos para archivos y backups: S3 (AWS), Blob Storage (Azure), Cloud Storage (GCP). Bloques para discos de VM y opciones de archivos compartidos. Clases de almacenamiento equilibran costo y frecuencia de acceso.

Bases de datos

Relacionales gestionadas: RDS/Aurora, Azure SQL Database, Cloud SQL. NoSQL: DynamoDB, Cosmos DB, Firestore/Bigtable. Los servicios gestionados automatizan respaldos, parches y alta disponibilidad según configuración.

Redes

Redes virtuales privadas (VPC/VNet), subredes, tablas de rutas, balanceadores de carga, DNS (Route 53, Azure DNS, Cloud DNS) y CDN. Una red bien segmentada (pública/privada) es clave para seguridad.

Contenedores y orquestación

Los tres ofrecen registro de imágenes y Kubernetes gestionado: Amazon EKS/ECS, Azure AKS, Google GKE. Si ya usas Docker, estos servicios facilitan escalar contenedores con control operativo.

Identidad, seguridad y gobierno

La gestión de identidad y acceso es el perímetro principal en la nube: IAM (AWS), Microsoft Entra ID + RBAC (Azure), Cloud IAM (GCP). Aplica privilegio mínimo, usa roles en lugar de credenciales de larga vida, habilita MFA y audita con registros (CloudTrail, Azure Monitor/Activity Log, Cloud Audit Logs).

  • Cifra datos en tránsito (TLS) y en reposo (claves gestionadas o propias).
  • Segmenta redes y limita exposición pública de recursos administrativos.
  • Automatiza políticas y cumplimiento con etiquetas/tags y guardrails.

Costos y operación

El modelo por uso requiere observabilidad financiera: dimensiona recursos, apaga entornos no productivos, usa instancias reservadas o planes de ahorro cuando el consumo sea estable y configura alertas de presupuesto. Herramientas nativas: AWS Cost Explorer/Budgets, Azure Cost Management, GCP Billing Reports.

# Ejemplos de CLIs oficiales
aws s3 ls
az group list
gcloud compute instances list

Para empezar, usa niveles gratuitos (free tiers) con límites y fechas claros, y elimina recursos de laboratorio para evitar cargos sorpresa. Documenta arquitectura con diagramas simples (cliente → balanceador → cómputo → base de datos/almacenamiento) para razonar dependencias y fallos.

Ruta de aprendizaje práctica

1) Crea una cuenta y configura alertas de costo. 2) Despliega un sitio estático en almacenamiento de objetos o una VM mínima. 3) Añade una base de datos gestionada. 4) Automatiza con infraestructura como código (CloudFormation/Bicep/Terraform) cuando domines lo básico.

Si te interesa esto, también mira

  • Docker y contenedores básicos — empaqueta apps para desplegarlas en la nube.
  • Linux terminal esencial — administra instancias y servicios cloud.
  • APIs REST: consumir y crear — integra servicios y automatiza con APIs cloud.
