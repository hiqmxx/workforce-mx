Quién entra a tu sitio o sistema, qué puede hacer y cómo lo proteges. Autenticación, autorización, contraseñas, 2FA, roles, permisos y errores comunes de seguridad.

🔐 Autenticación vs autorización

Autenticación es verificar quién eres: iniciar sesión con correo y contraseña, huella dactilar o un código.

Autorización es decidir qué puede hacer esa persona: ¿puede editar facturas? ¿sólo ver reportes? ¿borrar usuarios?

✓
Ejemplo: el repartidor se autentica en la app, pero solo está autorizado a ver sus entregas, no a cambiar precios ni borrar clientes.

🔑 Contraseñas seguras

✓
Única por servicio: si filtran una, las demás están a salvo.
✓
Largas (16+ caracteres): una frase aleatoria gana a una contraseña rara y corta.
✓
Gestor de contraseñas (obligatorio): Bitwarden (gratis, open source), 1Password o KeePassXC. Solo recuerdas una contraseña maestra fuerte.
✓
Nunca guardes contraseñas en bloc de notas, correos, Excel ni pegatinas en el monitor.
✓
Revisa filtraciones: haveibeenpwned.com → pon tu email → cambia las contraseñas filtradas ya.

📱 2FA (autenticación de dos factores)

Algo que sabes (contraseña) + algo que tienes (celular, app autenticadora o llave hardware).

✓
Actívalo en TODO: email, banca, redes, gestor de contraseñas, admin de tu web o hosting.
✓
Orden de seguridad: llave hardware (YubiKey) > app autenticadora (Authy, Google Auth, Microsoft Auth, Bitwarden) > SMS (mejor que nada, pero vulnerable a SIM swapping).
✓
Guarda códigos de respaldo: al activar 2FA te dan códigos de emergencia. Guárdalos en papel o en tu gestor de contraseñas.

👥 Roles de usuario y permisos

✓
Admin: acceso total.
✓
Editor / Ventas: CRM, clientes, facturas, pero no borrar usuarios ni cambiar configuración.
✓
Lectura: sólo ver reportes.
✓
Mínimo privilegio: cada quien solo lo que necesita para trabajar.
✓
Offboarding inmediato: revoca accesos el mismo día que alguien se va de la empresa.

🛡️ Protección de rutas

Rutas públicas: inicio, login, contacto.

Rutas privadas: /admin, /facturas, /usuarios, configuración.

✓
Siempre valida la sesión del servidor en cada ruta protegida; no confíes solo en ocultar el menú.
✓
Si no hay sesión válida, redirige al login.
✓
Ejemplo de check del servidor (pseudocódigo):
if (!usuario) {
  return redirect('/login')
}

💡 La regla de oro

Ocultar un enlace no es seguridad. Si alguien adivina la URL de /admin y no hay validación de sesión, entra aunque no vea el botón en el menú.
