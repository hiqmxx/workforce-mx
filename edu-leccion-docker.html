DevOps

Docker y
contenedores básicos

Empaqueta tu aplicación y sus dependencias en un contenedor portátil que se ejecuta igual en tu laptop, en el servidor y en la nube. Esta lección cubre conceptos, comandos y prácticas recomendadas desde la documentación oficial de Docker.

Qué es Docker y por qué importa

Docker es una plataforma para desarrollar, enviar y ejecutar aplicaciones en contenedores. Un contenedor es un paquete ligero y aislado que incluye el código, el runtime, librerías y configuración necesarios. A diferencia de una máquina virtual, los contenedores comparten el kernel del sistema anfitrión, por lo que arrancan en segundos y consumen menos recursos.

El problema clásico que resuelve Docker es “en mi máquina funciona”. Al encapsular dependencias, versiones de lenguaje y configuración del entorno, reduces sorpresas entre desarrollo, pruebas y producción. Esto facilita integración continua, despliegues reproducibles y escalado horizontal.

Imagen vs contenedor

Una imagen es una plantilla inmutable de solo lectura (capas). Un contenedor es una instancia en ejecución de esa imagen con una capa de escritura encima. Puedes crear muchos contenedores desde la misma imagen.

Arquitectura básica

Docker se compone principalmente de: el Docker Engine (daemon dockerd que construye y ejecuta contenedores), la CLI (docker) que envía comandos al daemon, y registries como Docker Hub donde se almacenan y distribuyen imágenes. Cuando ejecutas docker run, el cliente habla con el daemon; si la imagen no existe localmente, se descarga del registry configurado.

  • Dockerfile: receta declarativa para construir una imagen.
  • Image: artefacto versionado por etiquetas (nginx:1.27, python:3.12-slim).
  • Container: proceso aislado con su propio sistema de archivos, red y PID namespace.
  • Volume: almacenamiento persistente gestionado por Docker.
  • Network: red virtual para que contenedores se comuniquen por nombre.

Instalación y primeros comandos

En Windows y macOS se usa típicamente Docker Desktop; en Linux se instala Docker Engine desde los repositorios oficiales. Tras instalar, verifica con:

docker --version
docker run hello-world

Comandos esenciales del día a día:

# Listar contenedores en ejecución y todos
docker ps
docker ps -a

# Descargar una imagen y ejecutar un contenedor interactivo
docker pull ubuntu:24.04
docker run -it --name demo ubuntu:24.04 bash

# Ejecutar en segundo plano y mapear puertos
docker run -d -p 8080:80 --name web nginx:alpine

# Ver logs y entrar a un contenedor activo
docker logs -f web
docker exec -it web sh

# Detener, iniciar y eliminar
docker stop web
docker start web
docker rm web

# Imágenes locales y limpieza
docker images
docker image prune
docker system prune

El mapeo -p 8080:80 expone el puerto 80 del contenedor en el 8080 del host. La opción -d ejecuta en modo detached. Usa nombres (--name) para administrar contenedores con facilidad.

Crear imágenes con Dockerfile

Un Dockerfile define cómo construir una imagen capa por capa. Cada instrucción genera una capa cacheable, por eso el orden importa para aprovechar la caché.

# Dockerfile
FROM python:3.12-slim
WORKDIR /app

# Instalar dependencias primero (mejor caché)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copiar el resto del código
COPY . .

EXPOSE 8000
CMD ["python", "app.py"]

Construye y etiqueta la imagen, luego ejecútala:

docker build -t mi-api:1.0 .
docker run --rm -p 8000:8000 mi-api:1.0
  • FROM: imagen base. Prefiere variantes -slim o -alpine cuando sea viable.
  • WORKDIR: directorio de trabajo dentro de la imagen.
  • COPY/ADD: copia archivos (prefiere COPY salvo que necesites extracción automática).
  • RUN: ejecuta comandos en tiempo de build.
  • ENV: variables de entorno por defecto.
  • EXPOSE: documenta el puerto; no publica por sí solo.
  • CMD/ENTRYPOINT: comando por defecto al iniciar el contenedor.

Buenas prácticas

Usa .dockerignore para excluir .git, node_modules y secretos. Fija versiones de base, minimiza capas combinando comandos cuando tenga sentido, ejecuta como usuario no root (USER) y escanea imágenes en busca de vulnerabilidades.

Volúmenes y persistencia

Los contenedores son efímeros: su capa de escritura desaparece al eliminarlos. Para datos persistentes (bases de datos, uploads, configuración) usa volúmenes o bind mounts.

# Volumen nombrado gestionado por Docker
docker volume create datos_app
docker run -d -v datos_app:/var/lib/postgresql/data postgres:16

# Bind mount (mapea carpeta del host)
docker run -d -v C:\proyecto\site:/usr/share/nginx/html:ro -p 8080:80 nginx:alpine

Los volúmenes nombrados son la opción recomendada para producción porque Docker gestiona su ubicación y permisos. Los bind mounts son útiles en desarrollo para reflejar cambios del código en caliente.

Redes y comunicación entre contenedores

Docker crea redes bridge por defecto. En una red definida por el usuario, los contenedores se resuelven por nombre, lo que simplifica arquitecturas multi-servicio.

docker network create app-net
docker run -d --name db --network app-net -e POSTGRES_PASSWORD=secret postgres:16
docker run -d --name api --network app-net -p 8000:8000 mi-api:1.0
# Desde "api", el host "db" resuelve al contenedor de Postgres

Para entornos de desarrollo multi-contenedor, Docker Compose permite declarar servicios, redes y volúmenes en un archivo compose.yaml y levantarlos con un solo comando.

# compose.yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data
  api:
    build: .
    ports:
      - "8000:8000"
    depends_on:
      - db
volumes:
  pgdata:
docker compose up -d
docker compose logs -f
docker compose down

Seguridad y operación

  • Ejecuta procesos como usuario no privilegiado dentro del contenedor.
  • Limita capacidades y recursos (--memory, --cpus).
  • Mantén imágenes base actualizadas y reconstruye periódicamente.
  • No incluyas secretos en el Dockerfile; usa variables de entorno en runtime o gestores de secretos.
  • Usa etiquetas inmutables o digests para despliegues reproducibles.

Resumen operativo

Construye imágenes pequeñas y reproducibles, persiste datos con volúmenes, conecta servicios con redes, y automatiza con Compose. Con estas bases puedes avanzar a orquestadores como Kubernetes cuando la escala lo requiera.
